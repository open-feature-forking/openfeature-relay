UC-008 brings no new component type. What is left is to make the eight runners one product for an Extension Author:
- one entry point and one result shape;
- one way to declare a case not applicable, kept apart from the modes that change what a case asserts;
- the UC-008 cases each runner still lacks;
- proof that a module outside this repository can run them from the module cache.

## 0. Questions for the project lead

The recommendation comes first.

- **Q1, a shared contract package (step 6, A4, A5).** Four runners each declare their own copy of `Case{Name, Passed, Expected, Observed}`, `Report{Aborted, Cases}`, `Failed`, `FailedCases` and `missing(...)`: `synctest`, `telemetrytest`, `eventsinktest`, and `middlewaretest` (#67). `servicetest` returns `[]Result{Name, Err}`. `formattest` and `evaluatortest` return nothing. PR 2a.
  - **Recommendation:** `R/core/pkg/contracttest` with:
    - `Case` and `Report`;
    - `Need(input string, present bool, cases ...string)` for A1's message;
    - `ValidateWithout[F ~string](without []F, supplied map[F]bool) error`, generic so that each runner keeps its own typed `Feature` (finding 9);
    - `Report.Run(t *testing.T)`: one subtest per case, `Fatalf` once for an aborted run, and a not-applicable case logged with its reason.
  - The runners keep their packages and their typed `Inputs`.
  - *Alternative:* keep a copy per runner, held to one shape by a reflection test.

- **Q2, one entry point (step 1).** Today's entry points:

  | Runner | Today |
  |---|---|
  | `formattest` | `Run(t testing.TB, …)`; no report |
  | `evaluatortest` | `Run(t evaluatortest.T, …)`; no report |
  | `synctest` | `RunFetcher`, `RunTrigger`, `RunStreaming(t *testing.T, …)`; `Check…(t testing.TB, …) Report` |
  | `servicetest` | `Run(t *testing.T, …)`; `Check(f, in) []Result` |
  | `telemetrytest` | `Run(t *testing.T, …)`; `Check(t testing.TB, f, in) Report` |
  | `eventsinktest` | `Run(t *testing.T, …)`; `Check(t testing.TB, f, in) Report` |
  | `middlewaretest` (#67) | `Run(t *testing.T, …)`; `Check(f, in) Report` |

  PR 2a, 2b.
  - **Recommendation:** every runner offers `Run(t *testing.T, f <Factory>, in Inputs)` for authors, and `Check(t, f, in) contracttest.Report` for its own tests. `synctest` keeps `Run<Type>`/`Check<Type>` for its three component types. `Check` takes `evaluatortest.T`'s four-method interface, which `testing.TB` satisfies, so the runners' own fakes keep working (finding 7). No dispatcher over `any`.
  - *Alternative:* a dispatcher `contracttest.Run(t, factory any, inputs any)` on top. One name to learn, but a wrong `Inputs` type then fails at run time.

- **Q3, opt-outs and modes are two different things (A1, failure postcondition).**
  - **True opt-outs** leave a case unexercised:
    - `servicetest`'s `Without []Feature` (supplied and named fails; neither fails, naming the input);
    - `formattest`'s nil samples (`Incremental`, `Dropped`), skipped silently;
    - `evaluatortest`'s zero samples (`Disabled`, `AbsentDefault`, `Attribute`, `Paired`, `Shared`), skipped silently.
    - The silent ones contradict A1 and the failure postcondition: the run passes with a case not exercised.
  - **Declared modes** keep a case running with a different assertion:
    - `middlewaretest`'s `NoConfig` (a middleware without configuration must accept any configuration);
    - `middlewaretest`'s `NeverAnswers` (the answering and concurrency cases assert pass-through);
    - `telemetrytest`'s `NoBackend` (the flush and stall cases change);
    - `eventsinktest`'s `NoConfig`.
  - PR 2a, 2b.
  - **Recommendation:**
    - **Opt-outs:** every runner takes `Without []Feature` under `servicetest`'s rules. A case behind a named feature is reported as "not applicable (Without: …)" with its name.
    - **Modes:** stay typed fields, named alike in every runner (`NoConfig`, `NoBackend`, `NeverAnswers`). A case running in a mode states the mode in its `Expected` text, so the report shows which assertion ran.
    - **Spec:** amend UC-008's failure postcondition to "a run with a failed or missing case, or a case not exercised that the author did not declare not applicable, is never reported as passed". A1 gains the `Without` rule. The amendment covers opt-outs only.
  - *Alternative:* one mechanism for both, with modes as `Without` entries whose cases still run. Fewer field types, but "Without" then sometimes means "skip" and sometimes "assert otherwise".

- **Q4, the evaluator's test-harness case for third parties (BR-002 Evaluator row, UC-007 BR-004).** `test/evaluator-testkit` has the module path `github.com/open-feature/flagd/test/evaluator-testkit`. It finds the testbed's evaluator suite through `filepath.Dir(file)/../../test-harness`, which the module cache never contains, and it is not released.
  - **Licence, checked read-only on GitHub:**
    - At the pinned `v3.11.0`, `open-feature/flagd-testbed` has no `LICENSE`, `NOTICE` or `COPYING` in its root listing.
    - `GET repos/open-feature/flagd-testbed/license` returns 404, and the repository's `license` field is `null`.
    - Neither `package.json` nor the README names a licence.
    - So nothing grants redistribution of the suite, and revision 1's embedded copy has no basis.
  - **The upstream route:** an unmerged testbed branch (`feat/go-embed-module`) would make the testbed a Go module that exposes its assets through `embed.FS`. It does not embed `evaluator/`, and depending on it needs upstream work and a release, both outside this repository's containment.
  - **Recommendation (b):** keep the testkit in this repository and fix its module path (PR 4).
    - Its `Run` returns a `contracttest.Report`, one case per scenario.
    - UC-008 and UC-007 name the third-party case as an accepted gap: "an Extension Author's evaluator paired with flagd's format is checked against the test-harness suite only inside this repository".
    - The owner is UC-012, together with releasing.
    - Nothing is copied.
  - *Alternative (a):* the project lead allows an upstream change to the testbed that adds a licence and embeds `evaluator/` in its Go module. The testkit then depends on that module and works from the module cache.
  - *Alternative (c):* copy the suite once the testbed carries a licence that allows it.

- **Q5, how the external run proves a third party can run the suites (BR-004, C-001).** A `replace` onto the checkout keeps the runners' sources inside the checkout, so a relative path in a runner still resolves (finding 1). The repository is public, so a commit is fetchable by pseudo-version. PR 3.
  - **Recommendation:** `make test-contract-external`, inside `make test` (CI's existing `test` job). For each qualifying example module (Q6), it:
    - copies the module to a temporary directory outside the checkout;
    - drops its `replace` directives;
    - runs `GOWORK=off GOFLAGS=-mod=mod GOPROXY=direct GONOSUMDB=github.com/open-feature-forking/* go get R/core@$(git rev-parse HEAD)`;
    - runs `go test -race -count=2 ./...`.

    The runners then come from the module cache: no workspace, no submodule, no relative path. For an unpushed local commit, the target falls back to a `replace` onto a `git archive` copy of `core/` in a second temporary directory, which also has no submodules, and says so in its output. `-count=2` is the repeatability postcondition. No UC-012 gap is needed: a pseudo-version stands in for a tag.
  - *Alternative:* a separate CI job, scheduled or per push. It is visible on its own, but it adds a job to the PoC's CI list.

- **Q6, which example modules qualify, and engine modules' tests that need flagd (UC-007 BR-009, finding 6 and 11).**
  - **Already qualifying:** `test/sync-example`, `test/service-example` and `test/telemetry-example` each require only `R/core`.
  - **Does not qualify:** `test/configformat-example` requires the flagd module and `R/configformat/flagd`, through `endpoint_test.go`, `engine_test.go` and `keyvalue_test.go`. Those files cover UC-007's A5 and shadowed keys (`TestEngineServesBothFormats`, `TestShadowedKeys`) and UC-018's A2 and A3 (`TestTryInDistribution`, `TestSourceWithoutFormatIsRejectedByFlagd`).
  - **Affected downstream:** `test/inprocess-example/engine` requires `test/configformat-example`.
  - PR 3.
  - **Recommendation:**
    - Move those tests into a sibling test module, `test/configformat-example/distribution`. They stay in the extension's tree, and UC-007's and UC-018's coverage notes name the new path. The engine module then requires only `R/core` (UC-007 BR-009).
    - The external run's list is derived, not hand-kept: every `test/*-example` module whose `GOWORK=off go list -m all` contains no relay module but `R/core`.
    - A marker file, `testdata/contract-external.txt`, names the modules that must qualify. The target fails when a listed module stops qualifying, or when a qualifying one is missing from the file. #68's and #70's examples join by a line each.
  - *Alternative:* keep `test/configformat-example` as it is and leave it out of the external run. No move, but the engine example then never proves it runs outside the repository.

- **Q7, declaration checks (step 3, A2).** The validators are named `ValidateDeclarations` (sync, service) and `ValidateDeclaration` (telemetry, event sink, middleware). Configuration formats and evaluators have none; `evaluatortest` checks inline, `formattest` not at all. PR 2a.
  - **Recommendation:** `ValidateDeclarations(f) error` in every factory package, with the two missing ones added. Every runner calls it first and aborts naming the broken rule.
  - *Alternative:* keep both names; add only the two missing validators.

- **Q8, old signatures and fields (finding 10).** Nothing is tagged yet, and every caller of the runners is in this repository (their own tests, the example modules, #68 and #70).
  - **Recommendation:** migrate every caller in the same PR and keep no shims; C-004 allows the move. The changed names go into UC-015's list.
  - *Alternative:* deprecated wrappers, removed in UC-015's slice.

- **Q9, where an Extension Author reads how to run the contract (step 1).**
  - **Recommendation:** `docs/reference/contract-tests.md` with one row per component type (runner, inputs, `Without` features, modes, the example that uses it), plus a compile-checked `ExampleRun` per runner package. PR 5.
  - *Alternative:* godoc only.

## 6. Risks

- **Weakened contracts.** Seven runners are refactored, and a case could be loosened. Three things guard against it: PR 1's goldens now include each case's `Expected` text, so a swapped assertion shows; the broken-stub tests (2a7); and the rule that a golden changes only in a named commit.
- **Stack upkeep.** PR 2b carries 2a by merge commit and PR 5 carries 3 and 2b. Fixes land on their own branch and are merged upward.
- **Network in `make test`.** The external run fetches `R/core` by pseudo-version through `GOPROXY=direct`. CI has network access. Locally, an unpushed commit uses the `git archive` fallback, and the target prints which path it took.
- **C-004.** Changed runner signatures and the dropped `servicetest.Result` are listed for UC-015 (Q8).
- **NFR-006.** `core/pkg/contracttest` imports `testing`, `fmt`, `strings` and core only, pinned by a boundary row.
- **Containment.** Nothing reads from or writes to another repository. The testbed stays a pinned submodule, and Q4's alternative (a) is the project lead's call.
