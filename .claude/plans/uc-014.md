### Open (the plan assumes the recommendation)

- **Q13a, which modules get the new prefix.**
  - **Recommendation:** every **library** module: `core` and all new top-level modules. The **binary** modules `flagd` and `flagd-proxy`, and the test modules, keep `github.com/open-feature/flagd/...`.
  - *Why the libraries:* they are what providers import, so they must resolve from this repository with matching versions. If only the new modules moved, they would require `github.com/open-feature/flagd/core`. Outside this repository the Go proxy serves upstream core for that path, without `MetricsRecorder`, `ProtoVersionKey`'s new home or `sync/polling`, so nothing would build without `replace`.
  - *Why not the binaries:* they ship as images and are never imported. Renaming them rewrites every internal import in flagd (most of its files) and would conflict with every `upstream/main` merge, which CLAUDE.md makes routine. `go install github.com/open-feature/flagd/flagd@…` keeps meaning upstream flagd, so the docs' install instructions stay correct.
  - **Consequences:**
    - **Mixed prefixes:** binaries are upstream-prefixed, libraries relay-prefixed. That's allowed; replaces bridge it locally.
    - **Published Go provider:** pins upstream core, an unrelated path, so it is unaffected and there are no ambiguous imports.
    - **go.work and Dockerfiles:** directory-based, unaffected.
    - **release-please:** packages named by directory as before; tags `core/vX.Y.Z` and `<dir>/vX.Y.Z` in this repository.
    - **Docs:** the library install lines (in-process providers) name the relay prefix, from UC-015's guide.
    - **Later upstream move:** one mechanical PR rewrites the library module lines, imports and replaces back to `github.com/open-feature/flagd/...`. core then continues upstream's version line (v0.20.0). Any provider that adopted the relay paths in between migrates twice, which UC-015 must say.
  - **Alternatives:**
    - (a) Only the new modules move: cheapest now, but they require an upstream core that lacks their APIs, so they don't build outside this repository.
    - (b) Everything moves, binaries included: the whole flagd tree is rewritten, and every upstream merge conflicts.
  - **Version of the renamed core:** start the new path at v0.20.0, to keep upstream's lineage readable.
- **Q14, per-cloud blob modules and the module graph.**
  - gocloud.dev is **one** module whose `go.mod` requires the AWS, Azure and GCP SDKs. So `sync/gcs`, `sync/azblob` and `sync/s3` can each pull only their own SDK in the **package** graph, but all three SDKs remain in every blob module's **module** graph.
  - **Recommendation:** accept the package-level split now (checked per module), and make "per-cloud module graphs", which need native SDK clients instead of gocloud, a named gap owned by UC-003.
  - *Why:* the split is a move of existing code; replacing gocloud is a rewrite of three fetchers with new tests.

## 8. Risks

- **Mixed prefixes (Q13a).** Readers see `open-feature/flagd/flagd` importing `open-feature-forking/openfeature-relay/core`. It's deliberate, and the PR 4 text explains it.
  - The meter names and Prometheus scope labels keep the upstream literal: the code says `…/openfeature-relay/telemetry/otel` while the metrics say `…/flagd/core/pkg/sync/...`. A comment at the literal says why (C-003).
- **Upstream merges.** Upstream changes to core files now land on renamed imports and moved files. Each `upstream/main` merge into these files needs a manual port. That cost exists anyway after the carve; the binary modules keep their paths to limit it.
- **Blob per cloud (Q14).** The package graphs are split; module graphs still carry all three SDKs through gocloud.dev. Driver registration happens in each cloud module's `init`, so a distribution with all three behaves as today, as pinned by 1e and the integration tests.
- **Q10 coverage.** The evaluator section covers evaluation semantics. Provider behaviour (connection, events, selectors, sync payloads) waits for go-sdk-contrib's migration (UC-015). `TestInProcess` keeps testing flagd-full's sync side with the published provider.
- **C-003, metrics.** Pinned by 1d through the Prometheus gatherer. The reconnect is forced on the same address.
- **Mechanical PRs 4–6.** Package coverage, tidy and `GOWORK=off` builds, and image builds catch dropped packages, missing replaces and Docker binds.
- **Over-building.** No release tooling (UC-012), adapter or router (UC-007), flag sync format selection (UC-017), endpoint modules (UC-004/UC-001), native cloud SDKs or poller redesign (UC-003), telemetry factory (UC-006).
- **Containment.** go-sdk-contrib and flagd-testbed are read-only. The test harness is the existing submodule, and nothing is pushed beyond this repository.
