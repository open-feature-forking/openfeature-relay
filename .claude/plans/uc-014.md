## 0. Decisions and remaining questions

### Decided

- **Q2: OTel out of the sync providers.**
  - Design in section 4. flagd-full keeps every sync instrument it emits today, with no gap.
  - **Precision for Simon (finding 2):** this holds for the sync modules' **package** graph (`go list -deps`). A module that requires gRPC always has OTel in its **module** graph, because `google.golang.org/grpc`'s own `go.mod` requires `go.opentelemetry.io/otel`, `/metric`, `/sdk`, `/sdk/metric` and `/trace`, even though none of gRPC's packages import them.
  - So `sync/grpc` and anything requiring it can be OTel-free only at the package level; `sync/file` and core can be OTel-free in the module graph too.
- **Q3:** FR-044 and A5 are a gap owned by UC-017.
- **Q4:** steps 7–8, BR-008 and the adapter half of A6 are a gap owned by UC-007.
- **Q5 (changed by Q1):** the published Go provider pins core v0.19.0 and can't be built against the new core.
  - `test/integration` keeps running it unchanged; that tests flagd-full's flag sync side.
  - Acceptance of the embedded evaluator is Q10.
- **Q6:** A2 is a gap owned by UC-007/UC-019; A7 and A8 get no test.
- **Q7:** every consumer requires `core` and each new module in its transitive build list at `v0.0.0-00010101000000-000000000000`, with a `replace` to the local directory.
  - The new paths were never published by any module (the opposer checked the history of the deleted root module), so imports can't become ambiguous.
  - UC-012 releases core v0.20.0 before or with the new modules.
- **Q8:** keep the evaluator's compat `SetState` (flagd's runtime reaches flagd's format through it) and `store.NewFlags`; UC-015 retires `NewFlags`.
- **Q9:** the shared poller stays in core as the public `core/pkg/sync/polling`, because the internal rule is path-based. cron in core is the NFR-006 gap owned by UC-003.

### Open (the plan assumes the recommendation)

- **Q10, acceptance of the embedded evaluator (FR-041, BR-002, BR-005, steps 10–11).**

- **Q13, module path prefix.**
  - **Recommendation:** keep `github.com/open-feature/flagd/<dir>`.

**Why this shape:**
- **Paths** follow the ADR's tree.
- **Core** keeps interfaces, model and sync data types (glossary; NFR-006).
- **The store stays in core:** the format, evaluator and endpoints share it, and moving it into the evaluator would make flagd's format depend on the evaluator, which NFR-011 forbids.
- **Interfaces and shared keys stay at `core/pkg/evaluator`,** so endpoints depend on the interface. Only `flagd/pkg/evaluation` and `from_config.go` import `evaluator/jsonlogic`.
- **The ADR's endpoint modules** come with UC-004/UC-001.

**Move, not forward.**
- Forwarders in core would create a require cycle and break NFR-006 and NFR-011; forwarders in the new modules defeat the split.
- Old paths disappear from core v0.20.0. Pinned providers keep compiling.

**Release tags (UC-012):**
- Nine new series `<dir>/vX.Y.Z` from v0.1.0; core moves to v0.20.0, first or together.
- release-please gains nine non-overlapping packages.
- Nothing is `go get`-able in the incubator.

**UC-014 vs UC-015:** here, every in-repository importer moves and the old → new path table goes in the PR text. UC-015 does the guide, go-sdk-contrib's migration, the full provider suite, and retiring `NewFlags`.

## 4. Sync metrics without OTel packages in the sync modules (resolves the blocker)

**Two narrow interfaces, implemented in `telemetry/otel`, injected by whoever builds the sync providers.**

- **Generic sync recorder**, in `core/pkg/sync`:

  ```go
  type MetricsRecorder interface {
      RecordFlagConfigReceived(ctx context.Context, sourceType, uri, selector string)
  }
  ```

  Every sync provider takes it; nil means noop.
- **gRPC stream recorder**, in `sync/grpc`, because streams are this provider's concept:

  ```go
  type StreamMetricsRecorder interface {
      RecordStreamOpened(ctx context.Context, uri, selector string)
      RecordStreamClosed(ctx context.Context, uri, selector string)
      RecordReconnect(ctx context.Context, uri, selector string)
  }
  ```

  - `grpc.Sync` gains a `StreamMetrics StreamMetricsRecorder` field; nil means noop.
  - The calls at grpc_sync.go:167, 173, 188, 191 and 259 stay at the same points.
  - `client_stream_metrics.go` and the `Init` read of the global provider are deleted.
- **`telemetry/otel` implements both** (Go's structural typing means it doesn't import `sync/grpc`):
  - `NewSyncMetricsRecorder(mp)`: today's `syncmetrics.Recorder`, unchanged. Meter `github.com/open-feature/flagd/core/pkg/sync/syncmetrics` as a string literal, same instruments, attributes and `SanitizeURI`.
  - `NewGRPCStreamMetrics(mp)`: today's `clientStreamMetrics`, unchanged. Meter `github.com/open-feature/flagd/core/pkg/sync/grpc` as a string literal, the same two instruments, names and descriptions, no unit, the same dual attribute set.
  - A nil `mp` falls back to `otel.GetMeterProvider()` at construction, as today.
  - The attribute name constants (`AttrLegacyProvider` and the others) move with them.
  - Both are nil-receiver safe, because a typed-nil pointer stored in the interface passes a `!= nil` check.
- **gRPC client telemetry.** `sync/grpc` drops `otelgrpc` and gains `DialOptions []grpc.DialOption`, appended on both the default and the override path, exactly where the stats handler sits today.
- **flagd-full (C-003, no gap).** `from_config.go` builds both recorders after `BuildMetricsRecorder` has set the global provider, the same point and provider as today. It passes them, plus `grpc.WithStatsHandler(otelgrpc.NewClientHandler())`, through `sync/builder`.
- **flagd-proxy gets no injection.** Today its instrumentation records into the noop global (no SDK installed), so nothing observable changes, and injecting would add the OTel SDK to its graph.

**Why not the alternatives:**
- **Event bus:** arrives in UC-004, and metrics aren't domain events.
- **Decorator around `ISync`:** the counters fire at provider-specific points (stream open/close/reconnect, and receipt before emission), which a channel decorator can't observe.

**Full version:** UC-003 puts both recorders and transport instrumentation into the sync factory's injected dependencies (and decides whether stream metrics generalize beyond gRPC). UC-006's telemetry provider factory supplies the OTel implementations, and noop for FR-024.
