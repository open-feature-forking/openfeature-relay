# UC-014 plan: Embed Evaluator in In-Process Provider (PoC slice 2)

Issue #26. Base: `main` @ 66bc9f9: UC-018 PRs 1–4 are merged, and PR #38 (example format) is in CI. Every PR description starts with `Part of #26`.

## 0. Spec questions (the plan assumes the recommendation)

- **Q1, how to split the modules.**
  - FR-040 and the postconditions are about the module graph, not only the package graph. Today the evaluator's packages are clean (`go list -deps` passes NFR-005), but the `core` module requires OTel, gRPC, connect, k8s and the cloud SDKs, so every importer gets them in its graph.
  - **Recommendation:** split by carving out, with **unchanged import paths**. `core` becomes the light core module (NFR-006). Every heavy package and the two embeddable components get a nested `go.mod` in the directory they already live in.
  - In-process providers then change only `go.mod`, never an import (C-004 allows more; UC-015 shrinks).
  - Alternative: new top-level module paths. That means import rewrites in flagd, flagd-proxy and every provider.
- **Q2, OTel through the sync providers.**
  - `sync/file` and `sync/grpc` record sync metrics through `sync/syncmetrics`, which imports the OTel metric API. Even a file-only provider therefore carries `go.opentelemetry.io/otel`.
  - **Recommendation:** accept for UC-014. NFR-005 binds only the evaluator and flagd's configuration format; the sync metrics move behind the telemetry provider factory in UC-003/UC-006 (named gap).
- **Q3, FR-044 and A5 (a flag sync request names its configuration format).**
  - This needs the flag sync endpoint to select documents by format, and a way to carry the name without changing the protobuf (C-005), for example a request header like `Flagd-Selector`.
  - **Recommendation:** gap owned by UC-017 (flag sync endpoint, flagd-sync). Today every request gets flagd's format, which already holds the "default" half of BR-007.
- **Q4, typed adapter (steps 7–8, BR-008, and the adapter half of A6).** **Recommendation:** gap owned by UC-007. Providers keep calling today's typed `Resolve*Value`.
- **Q5, acceptance without touching go-sdk-contrib (containment).**
  - **Recommendation, part 1:** `test/integration` already runs the published Go provider v0.8.0 in-process against flagd (`TestInProcess`, CI job `integration-test`). Add `replace` directives so that provider compiles against this repository's core, evaluator and format modules. The in-process suite then runs on our embedded evaluator (steps 10–11, BR-002, BR-005).
  - **Recommendation, part 2:** a minimal in-repo embedding example covers the module graph postconditions, which the Go provider can't show because it also bundles RPC mode.
- **Q6, flows with no system behaviour, or owned later.** **Recommendation:**
  - A2 (vendor engine module) is a gap owned by UC-007 (engine module, evaluator factory) and UC-019 (Flagsmith).
  - A7 (no hooks) and A8 (scenario fails, process only) get no test.
- **Q7, unpublished modules (containment: no releases).** **Recommendation:** consumers (`flagd`, `flagd-proxy`, `test/*`, the example) require each new module at `v0.0.0-00010101000000-000000000000`, with a `replace` to the local directory. Builds work with and without `go.work`. UC-012 swaps them for versions at release.
- **Q8, the evaluator's compat `SetState`.** The published provider calls `evaluator.SetState` and `store.NewFlags`. **Recommendation:** keep both. The evaluator module therefore requires flagd's configuration format module (allowed direction, NFR-011); UC-015 retires them.

## 6. Risks

- **Internal packages across nested modules.** If `sync/internal/*` can't be imported from the carved sync modules, move `bloburi` and `polling` into the module that owns them. That changes no public path, but step 2 stops and reports first.
- **Ambiguous imports.** A consumer that requires a published core still holding a carved package, plus the new module, fails with "ambiguous import". The replaces to local core (Q7) avoid it here; UC-012 must release core and the carved modules together, and UC-015 documents the bump.
- **`go test ./core/pkg/...` in workspace mode.** Directory patterns should span every workspace module. If `test-core` loses nested packages, list the module directories explicitly; coverage numbers in CI show it.
- **Dockerfiles.** `go work init ./core ./flagd` won't see nested modules; the replaces still resolve them because the build context is the repository. Verified by the image gate.
- **C-003.** No code changes, only `go.mod` boundaries. The integration suites and the pinned tests prove behaviour; the image name and CLI are untouched.
- **NFR-001.** Evaluation code is unchanged, so allocs/op should be identical; the benchmark gate catches a target that silently stops running.
- **Over-building.**
  - No release tooling (UC-012), no typed adapter or router (UC-007), no flag sync format selection (UC-017), no flagd module split (UC-001).
  - The example is a test fixture, not a provider.
- **Containment.** go-sdk-contrib stays read-only; the published v0.8.0 is consumed from the module proxy, as `test/integration` already does.
