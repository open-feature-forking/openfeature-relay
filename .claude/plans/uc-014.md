## 3. Module layout

New modules use the path `github.com/open-feature/flagd/<dir>`. This follows the ADR's module structure (modular-builder.md, "Module structure").

| Module dir | Package(s) | Contents, from | Requires |
|---|---|---|---|
| `core` | as today | **Core module** per the glossary (factory interfaces, flag model, sync data types) plus the store every component shares: `model`, `logger`, `store`, `sync` (`ISync`, `DataSync`, `SourceConfig`, **`MetricsRecorder`**), `sync/polling` (public, was internal, Q9), `sync/testing`, `configformat` (+ `formattest`), `evaluator` (**interfaces only**: `IEvaluator`, `IResolver`, `AnyValue`, `NewAnyValue`, `mock`), `service` (light), `service/ofrep` (models), `utils`, `fips`, `certreloader`, `notifications` | uuid, go-memdb, cron (Q9), zap, protobuf, yaml, gomock, testify |
| `evaluator/jsonlogic` | `jsonlogic` (+ `mock` if needed) | Implementation from `core/pkg/evaluator`: `NewJSON`, `JSON`, `Resolver`, fractional, semver, string comparison | `core`, `configformat/flagd`, jsonlogic, murmur3, cbor, x/mod |
| `configformat/flagd` | `flagd`, `flagdtest` | From `core/pkg/configformat/flagd`; `flagdtest` is UC-018's table from `core/internal/flagconfigtest` | `core`, jsonschema, flagd-schemas |
| `sync/file` | `file` | From `core/pkg/sync/file` | `core`, fsnotify |
| `sync/grpc` | `grpc`, `credentials`, `nameresolvers`, `mock` | From `core/pkg/sync/grpc/...` | `core`, gRPC, buf-generated sync |
| `sync/http` | `http` | From `core/pkg/sync/http` | `core` |
| `sync/blob` | `blob`, `bloburi` (public, because `sync/builder` uses it and the internal rule is path-based) | From `core/pkg/sync/blob` and `sync/internal/bloburi` | `core`, gocloud |
| `sync/kubernetes` | `kubernetes` | From `core/pkg/sync/kubernetes` | `core`, k8s |
| `sync/builder` | `builder`, `mock` | From `core/pkg/sync/builder`. It takes the metrics recorder and gRPC dial options from its caller, so it imports no OTel | Every sync module (it imports `sync/blob/bloburi`) |
| `telemetry/otel` | `telemetry` (Q11) | From `core/pkg/telemetry`, plus the OTel sync metrics recorder (section 4) | `core`, OTel SDK, otelgrpc, connect |

**Why this shape:**
- **Paths.** It matches the ADR's tree (`core/`, `sync/<x>/`, `evaluator/jsonlogic/`, `telemetry/otel/`).
- **Core stays light** (glossary: interfaces, model, sync data types; NFR-006).
- **The store stays in core.** Formats, evaluators and endpoints all write or read it (UC-018 `Settings.Store`). Putting it in `evaluator/jsonlogic`, as the ADR's sentence suggests, would make `configformat/flagd` depend on the evaluator, which NFR-011 forbids.
- **The evaluator interfaces stay at `core/pkg/evaluator`.** Endpoints in flagd depend on the interface, not on JsonLogic (ADR, factory interfaces in core). UC-007 reshapes them.
- **Service modules.** The ADR's endpoint modules (`service/flag-evaluation`, `service/ofrep`, `service/flag-sync`) are carved from `flagd/` in UC-004/UC-001, not here. `core/pkg/service` only loses its connect field, which moves to flagd's `ConnectService` configuration.

**Move, not forward.**
- The old paths disappear from core. Deprecated forwarding packages in core would make core require the new modules, which require core: a cycle, and NFR-006/NFR-011 broken.
- Forwarders in the new modules pointing back at core defeat the split.
- Providers pinned to core ≤ v0.19.x keep compiling unchanged, because they never see the new core.

**Release tags (UC-012):**
- Nine new series (`evaluator/jsonlogic/vX.Y.Z`, `configformat/flagd/…`, `sync/{file,grpc,http,blob,kubernetes,builder}/…`, `telemetry/otel/…`), each starting at v0.1.0.
- Core moves to v0.20.0 (packages removed; v0 minor bump), released before or with them.
- release-please gains nine packages; there are no overlapping directories, so core needs no `exclude-paths`.
- Nothing here is `go get`-able inside the incubator, because the paths resolve to upstream.

**Split between UC-014 and UC-015:**
- **Here:** every importer in this repository moves to the new paths (`flagd`, `flagd-proxy`, `test/*`, examples), and the old paths are removed. PR text carries the old → new path table.
- **UC-015:** the migration guide (FR-043) built from that table, go-sdk-contrib's provider migration, the full in-process suite on that provider, and retiring `NewFlags`.

## 4. Sync metrics without OTel in the sync modules

**Recommendation: a recorder interface in core, injected by whoever builds the sync providers.**

- `core/pkg/sync` gains:

  ```go
  type MetricsRecorder interface { RecordFlagConfigReceived(ctx context.Context, sourceType, uri, selector string) }
  ```

  It also gains `NoopMetricsRecorder` and the `Source*` constants. Providers take a `MetricsRecorder`; nil means noop.
- `telemetry/otel` provides `NewSyncMetricsRecorder(mp metric.MeterProvider)`. It is today's `syncmetrics.Recorder`, with the same meter name `github.com/open-feature/flagd/core/pkg/sync/syncmetrics` as a string literal, the same instruments, attributes and `SanitizeURI`.
- `sync/grpc` drops `otelgrpc` and gains `DialOptions []grpc.DialOption`, always appended, separate from `GrpcDialOptionsOverride`. `sync/builder` passes both options through.
- **flagd-full keeps today's telemetry (C-003, no gap).**
  - `from_config.go` builds `telemetry.NewSyncMetricsRecorder(nil)` instead of `syncmetrics.NewRecorder(nil)`.
  - It passes `grpc.WithStatsHandler(otelgrpc.NewClientHandler())` into the builder's dial options.
  - flagd-proxy does the same where it builds gRPC syncs.

**Why not the alternatives:**
- **Event bus:** it arrives in UC-004, and metrics are not domain events. UC-020's event sinks may later consume sync events, but metrics shouldn't wait for that.
- **Decorator around `ISync`:** it could count `DataSync`s on the channel. But today's counter fires at provider-specific points (grpc_sync.go:147, 272; filepath_sync.go:204) that don't map one-to-one to emitted payloads, so it risks changing values. UC-003 may evaluate it with the pin from PR 1.

**Full version:** UC-003 puts `MetricsRecorder` (and transport instrumentation) into the sync factory's injected dependencies. UC-006's telemetry provider factory supplies the implementations, and noop in distributions without telemetry (FR-024).
