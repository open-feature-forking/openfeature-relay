## 0. Spec questions (the plan assumes the recommendation)

- **Q1, the evaluator interface (changed by findings 1 and 3).**
  - **Recommendation:** one method in `R/core/pkg/evaluator`:

    ```go
    Evaluate(ctx context.Context, req Request, dst []Result) ([]Result, model.Metadata, error)
    ```

  - **`Request`** fields:

    | Field | Meaning |
    |---|---|
    | `Selector store.Selector` | |
    | `FlagKey string` | Single-key requests, when `FlagKeys` is nil and `Bulk` is false |
    | `FlagKeys []string` | Explicit keys; used by the router when it splits a bulk request |
    | `Bulk bool` | Set by bulk callers, and preserved when the router splits keys |
    | `Context map[string]any` | |
    | `TypeHint Type` | Single-key only |
    | `Attributes map[string]any` | |

  - **`Result`:** `FlagKey`, `Value any`, `HasValue bool`, `Variant`, `Reason`, `ErrorCode`, `ErrorMessage`, `Metadata`.
  - *Why:*
    - BR-006 makes bulk the primary operation and a single key the same call.
    - A dedicated `FlagKey` field avoids the one-element key slice that escapes through the interface call (the opposer measured 1 alloc per call), and a pooled `dst` avoids the result slice. So the single-flag path that NFR-001 gates adds nothing.
    - `Bulk` tells flagd's evaluator when its bulk rules apply, independent of how the router split the keys.
- **Q2, the typed adapter's scope (changed by finding 1).**
  - **Recommendation:** `R/core/pkg/evaluator/typed` implements today's `IResolver` on top of any `Evaluator`.
  - It owns:
    - the requested-type checks
    - integer and float conversion with the `WithStrictNumericRange` option (TODO #2101)
    - absent value → caller's default
    - the **single-call** legacy rule, decidable from `HasValue=false` with reason `DEFAULT`: under `ProtoVersionKey`, no default variant → `FLAG_NOT_FOUND`
  - **Stay in `evaluator/flagd`,** because they depend on the flag's default-variant type, which a `Result` doesn't carry:
    - the bulk rule that a variant must match the default variant's type (applies when `Bulk` is set)
    - the legacy bulk skip of flags whose default variant is absent or non-standard (applies when `Bulk` is set and `ProtoVersionKey` is in `ctx`; that key already lives in `R/core/pkg/evaluator`)
  - *Why:* endpoints keep their typed calls (C-003), and one adapter serves endpoints and in-process providers (BR-004).
- **Q3, reasons and error codes vs BR-010 (changed by finding 6).**
  - **Recommendation:**
    - The JsonLogic evaluator's `ERROR` code (json.go:389, when the context fails to marshal) becomes `GENERAL` with the message.
    - `FALLBACK` never leaves an evaluator (`HasValue=false`, reason `DEFAULT`); the adapter restores it toward the endpoints.
    - `FLAG_DISABLED` stays, mapped only by `errFormat` and never produced.
  - **Who sees the change:** endpoint clients can't reach `ERROR`. `structpb.AsMap()` turns NaN and Inf into strings, and OFREP's JSON has no NaN. **In-process callers can**, by putting `math.NaN()`, a `func` or a `chan` in the context; for them the error text changes from `ERROR` to `GENERAL`. This goes in the PR text and in UC-015's guide.
  - *Why:* the contract can assert BR-010 for every evaluator, flagd's included.
- **Q4, consistent resolution (changed by findings 3 and 8).**
  - **Recommendation:** `R/core/pkg/store` gains `View()`, returning a **concrete** value type (one memdb read transaction, with `Get`, `GetAll` and `Documents`). `Evaluate` uses it for every read.
  - **`NewJSON` over a foreign `IStore`** (json.go:103-111) keeps per-call `Get`/`GetAll` as today, without the BR-011 guarantee. `setstate_foreign_store_test.go` stays green, and UC-015 decides whether that path retires.
  - *Why:* BR-011 is met wherever the store is ours, and the value type keeps the view from escaping.
- **Q5, evaluator and format pairing in the runtime.**
  - **Recommendation:** an evaluator factory whose configuration format the distribution lacks fails startup, listing the formats. A format without an evaluator is allowed: its keys resolve to `FLAG_NOT_FOUND`, and startup logs a warning naming it.
  - *Why:* BR-002 makes the pairing mandatory; a configuration proxy (UC-017) has formats without evaluators. FR-018's manifest check is UC-001.
- **Q6, request attributes (A3).**
  - **Recommendation:** `Request.Attributes` is filled from a context key in `R/core/pkg/evaluator`. Middleware sets it in UC-005 (FR-047); here the test sets it.
  - *Why:* the evaluator half of A3 is testable now.
- **Q7, A5 without a builder.**
  - **Recommendation:** `FromConfig` with the example engine's factories and a file source naming its format, then the real flag evaluation (connect) and OFREP endpoints over `httptest`.
  - The manifest and `replace` part is a gap owned by UC-001.
- **Q8, the example engine module.**
  - **Recommendation:** extend `test/configformat-example` with an `evaluator` package and factory, so the module is an engine module (A1, FR-048). Its UC-018 tests stay unchanged.
  - *Why:* an engine module is format plus evaluator in one module.
- **Q9, where the contract lives.**
  - **Recommendation:**
    - The format-independent cases go in `R/core/pkg/evaluator/evaluatortest` (imports `testing` and core only).
    - The flagd suite part goes in `test/evaluator-testkit` as an exported `testkit.Run(t, factory)` (BR-007, A2).
    - **Characterization tests that compare the adapter with today's typed results live in `R/evaluator/flagd`, never in core** (finding 2): core importing `evaluator/flagd`, even from a test, breaks core's module-graph row and creates a require cycle.
  - *Why:* core and embedders never inherit godog or the JsonLogic engine.
- **Q10, A6 (abandon).** **Recommendation:** no test, because the flow has no system behaviour.

**How the router resolves a request (finding 7):**
- **One evaluator registered** (flagd-full): delegate directly. That is the NFR-001 fast path, and today's shape, including duplicates across flag sets.
- **Otherwise,** through one `View()`:
  1. **Collect.** Read the documents in the request's selector (source and flag-set filters).
  2. **Pick per (flag set, key),** mirroring `collect`: for each pair, the document whose source has the highest priority wins. A bulk request without a flag-set selector therefore returns one entry per flag set holding the key, as the flags table does today.
  3. **Ties:**
     - The same key in two flag sets of **one source** isn't a router decision. Both entries go to that source's format with `Bulk` preserved, and a single-key request without a flag-set selector is passed to that format's evaluator, which decides as today (`store.Get`'s rule for flagd).
     - Across sources, priority never ties, because indexes are unique.
  4. **Evaluate.** Group by format, call each evaluator once with its keys, and merge in (flag set, key) order.
- **Errors:**
  - A key with no evaluator, or an unknown key, returns `FLAG_NOT_FOUND`.
  - An evaluator error becomes per-key `GENERAL` results.

**The contract's format-independent cases:**
- Every error code is one of OpenFeature's.
- Every reason is an OpenFeature reason or an uppercase vendor reason without parameters.
- Disabled → `HasValue=false`.
- Absent default → `HasValue=false`, never a zero value for the hint.
- Bulk equals the single results key by key, except the documented bulk-only rules, which the samples declare.
- An unknown key → `FLAG_NOT_FOUND`.
- Concurrent resolution with updates under `-race`: two flags that are always updated together never disagree.
- Attributes reach the evaluator.
- Each failure reports expected vs observed (A4).

## 7. Risks

- **C-003.**
  - Endpoints keep their typed calls; only their parameter type widens to `IResolver`.
  - Every typed outcome is pinned by 1a, and bulk shapes, including the v1 skip and duplicates across flag sets, by 1b.
  - Intended changes:
    - `ERROR` → `GENERAL`, reachable only in-process (Q3).
    - Bulk resolution reading one snapshot (Q4).
- **NFR-001.**
  - `FlagKey` instead of a key slice, a pooled `dst`, a concrete `View`, and the single-evaluator fast path.
  - `TestAdapterAllocs` measures the real path, and the bulk benchmark covers `ResolveAllValues`.
  - If allocs still rise, step 5 stops and reports with numbers.
- **Module graph.** Adapter-vs-JsonLogic tests live in `evaluator/flagd`. Core's `typed` tests use fakes only, and the module-graph rows catch a slip.
- **Router semantics.**
  - Per (flag set, key), mirroring `collect`. Same-source ties are left to the format's evaluator; cross-source ties can't happen.
  - Mixed distributions are new behaviour covered by step 7 and step 8 tests; flagd-only keeps today's path.
- **Compat API.** `NewJSON`'s typed methods and the foreign-`IStore` path stay. UC-015 guides embedders to `typed` and decides the foreign-store path's future.
- **Over-building.**
  - No middleware (UC-005), endpoint factories or event bus (UC-004), builder (UC-001), or vendor engine (UC-019).
  - The keyvalue engine is a fixture.
- **Containment and a public repository.** No other repository is touched. Plans and PR texts name roles, never people.
