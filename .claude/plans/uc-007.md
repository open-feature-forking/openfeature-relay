## 0. Spec questions (the plan assumes the recommendation)

- **Q1, the evaluator interface.**
  - **Recommendation:** one bulk method in `R/core/pkg/evaluator`:

    ```go
    Evaluate(ctx context.Context, req Request, dst []Result) ([]Result, model.Metadata, error)
    ```

    - `Request{Selector store.Selector; FlagKeys []string /* nil = every flag of the selector */; Context map[string]any; TypeHint Type /* single-key requests only */; Attributes map[string]any}`
    - `Result{FlagKey string; Value any; HasValue bool; Variant, Reason, ErrorCode, ErrorMessage string; Metadata model.Metadata}`
    - Results are appended to `dst`.
  - *Why:*
    - BR-006 makes bulk the primary operation and a single key the same call.
    - Appending into a caller buffer lets the typed adapter reuse a pooled slice, so the single-flag path doesn't add an allocation (NFR-001 gates evaluator benchmarks on allocs/op).
- **Q2, the typed adapter's scope.**
  - **Recommendation:** `R/core/pkg/evaluator/typed` implements today's `IResolver` (`Resolve<Type>Value`, `ResolveAsAnyValue`, `ResolveAllValues`) on top of any `Evaluator`.
  - It owns:
    - the requested-type checks
    - integer and float conversion, including the `WithStrictNumericRange` option (TODO #2101)
    - absent value → caller's default
    - the legacy-proto behaviours that today hide in the evaluator behind `ProtoVersionKey`: no default variant → `FLAG_NOT_FOUND`, and the bulk skip of untyped flags
  - flagd's rule that a variant must match the type of the default variant in bulk stays in `evaluator/flagd`. It is a rule of flagd's flag model, not a requested-type check.
  - *Why:* endpoints keep calling `IResolver` unchanged, so the phase-1 span decorator and the endpoint tests stay pinned (C-003), and one adapter serves endpoints and in-process providers (BR-004).
- **Q3, reasons and error codes today vs BR-010.**
  - The JsonLogic evaluator returns error code `ERROR` (`model.ErrorReason`) when marshalling the evaluation context fails (json.go:389). That code isn't one of OpenFeature's.
  - It uses the internal reason `FALLBACK`, which endpoints translate to `DEFAULT` or a reason-only response.
  - **Recommendation:**
    - `ERROR` becomes `GENERAL` with the message. It can't be reached from a protobuf or JSON context, so no observable change is expected.
    - `FALLBACK` never leaves an evaluator: the result is `HasValue=false` with reason `DEFAULT`, and the adapter restores today's `FALLBACK` toward the endpoints.
    - `FLAG_DISABLED` is only mapped by the legacy endpoint's `errFormat` and never produced, so it stays.
  - *Why:* the contract can then assert BR-010 for every evaluator, flagd's included.
- **Q4, consistent resolution (BR-011).**
  - Today a bulk resolution reads `GetAll` in one memdb transaction, then calls `store.Get` per flag in new transactions, so a concurrent update can mix.
  - **Recommendation:** `R/core/pkg/store` gains a read view (one memdb read transaction) that `Evaluate` uses for all its reads.
  - *Why:* this is what BR-011 states, it is invisible without concurrent updates, and it saves transactions, so allocs/op don't rise.
- **Q5, evaluator and format pairing in the runtime.** FR-018's manifest check is UC-001.
  - **Recommendation:**
    - At runtime, an evaluator factory whose configuration format the distribution lacks fails startup, listing the formats.
    - A format without an evaluator is allowed; a key held only by such a format resolves to `FLAG_NOT_FOUND`, and startup logs a warning that names the format.
  - *Why:* BR-002 makes the pairing mandatory. A configuration proxy (UC-017) legitimately has formats without evaluators.
- **Q6, request attributes (A3).**
  - **Recommendation:** `Request.Attributes` is filled from a context key in `R/core/pkg/evaluator`. Middleware sets it in UC-005 (FR-047); here the test sets it directly.
  - *Why:* the evaluator half of A3 is testable now, and the middleware half is a named gap.
- **Q7, A5 without a builder.**
  - **Recommendation:** as UC-018 did. A5's test builds the runtime through `FromConfig` with the example engine's factories and a file source naming its format, then calls the real flag evaluation (connect) and OFREP endpoints over `httptest`.
  - The manifest and `replace` part is a gap owned by UC-001.
- **Q8, where the example engine module lives.**
  - **Recommendation:** extend `test/configformat-example` (the keyvalue format from UC-018) with an `evaluator` package and factory, so the module is an engine module (A1, FR-048). Its UC-018 tests stay unchanged.
  - *Why:* an engine module is exactly "format plus evaluator in one module"; a second example module would duplicate the format.
- **Q9, where the contract lives.**
  - **Recommendation:**
    - The format-independent cases go in `R/core/pkg/evaluator/evaluatortest`, like `configformat/formattest`. It imports only `testing` and core.
    - The flagd suite part (BR-007, A2) goes in `test/evaluator-testkit` as an exported `testkit.Run(t, factory)`, because it needs godog and the submodule.
  - *Why:* core and embedders never inherit godog.
- **Q10, A6 (abandon).** **Recommendation:** no test, because the flow has no system behaviour.

## 2. Facts from the base

- **`R/core/pkg/evaluator`** holds `IEvaluator` (`SetState` plus `IResolver`), `IResolver` (five typed methods, `ResolveAsAnyValue`, `ResolveAllValues`), `AnyValue`, `ProtoVersionKey` and `SelectorMetadataKey`.
- **flagd's endpoints use `IResolver`:**
  - three connect services through `resolve[T]` with `s.eval.Resolve<Type>Value`
  - OFREP through `ResolveAsAnyValue` and `ResolveAllValues`
  - wrapped by the phase-1 `TraceEvaluations` decorator
  - `errFormat` (flag_evaluator.go:412-425) maps error codes to connect codes
- **`R/evaluator/flagd`** (json.go):
  - `evaluateVariant` returns variant, variants, reason, metadata and error, reading the flags table through `store.Get` with the context's selector.
  - `resolve[T]` asserts the requested type and turns `FALLBACK` and `DISABLED` into zero values.
  - `ResolveInt`/`ResolveFloat` convert numbers, with the strict-range option.
  - `ResolveAllValues` calls `GetAll`, then types each flag by its default variant's value, then calls `store.Get` per flag.
  - The `ProtoVersionKey` branches live here (lines ~173, 403, 429).
- **Store:**
  - The flags table holds only flagd's flags. Priority is the source's index in the store's source list, and a higher index wins (store.go:190, 265, 355).
  - The `documents` table (UC-018) holds every format's documents, flagd's included, with `FlagKeys` and `FlagSet` per source.
- **UC-014's acceptance:** `test/evaluator-testkit` runs the testbed evaluator suite through the typed `Resolve*Value`.
- **The keyvalue example:** `test/configformat-example` has a format only (UC-018).

## 3. Design in brief

| Piece | Where | What |
|---|---|---|
| Interface | `R/core/pkg/evaluator` | `Evaluator` (Q1), `Factory{Type() string; ConfigurationFormat() string; Create(Settings) (Evaluator, error)}`, `Settings{Store *store.Store; Logger *logger.Logger; Config map[string]any}` (no telemetry, BR-008), `Type` hints, the attributes context key (Q6). The legacy `IEvaluator`/`IResolver` stay for compat and are implemented by `typed` |
| Read view | `R/core/pkg/store` | `View(ctx) ReadView` with `Get`, `GetAll`, `Documents` over one read transaction (Q4) |
| Typed adapter | `R/core/pkg/evaluator/typed` | `typed.New(ev Evaluator, opts...)` returns an `IResolver` (Q2). A `sync.Pool` of 1-element `[]Result` buffers keeps single-flag calls allocation-neutral |
| Router | `R/core/pkg/evaluator/router` | `router.New(store, map[format]Evaluator)` is itself an `Evaluator` (FR-035, BR-001) |
| Contract | `R/core/pkg/evaluator/evaluatortest` | `Run(t, factory, Samples)` with format-independent cases (below) |
| flagd suite in the contract | `test/evaluator-testkit` | `testkit.Run(t, factory)`: the testbed evaluator suite through `typed` over the factory's evaluator (BR-007, A2) |
| JsonLogic evaluator | `R/evaluator/flagd` | Implements `Evaluate` over a read view and gets a `Factory` (format `flagd`). `NewJSON`'s typed methods stay as thin wrappers over `typed` for compat |
| Runtime | `flagd/pkg/runtime` | `Config.Evaluators []evaluator.Factory` (flagd's always present). Endpoints get `TraceEvaluations(typed.New(router))`; `SetState` stays on the JSON evaluator (UC-018 path). Pairing per Q5 |
| Engine example | `test/configformat-example` | New `evaluator` package (keyvalue evaluator over `store.Documents`, honouring `Request.Attributes`) and factory (Q8) |

**How the router resolves a request:**
- **One evaluator registered** (flagd-full): delegate directly, with no document lookup. That is the NFR-001 fast path.
- **Otherwise:**
  1. Read the documents in the request's selector (source and flag-set filters) through the read view.
  2. Map each key to the document whose source has the highest priority. That is the same precedence the flags table uses, so shadowed keys (the UC-018 gap) resolve consistently.
  3. Group the keys by format and call each evaluator once with its keys.
  4. Merge the results in key order.
- **Errors:**
  - A key with no evaluator returns `FLAG_NOT_FOUND` (Q5).
  - An unknown key returns `FLAG_NOT_FOUND`.
  - An evaluator error becomes per-key `GENERAL` results.

**The contract's format-independent cases** (`evaluatortest`):
- Every error code is one of OpenFeature's.
- Every reason is an OpenFeature reason or an uppercase vendor reason without parameters.
- Disabled → `HasValue=false`.
- Absent default → `HasValue=false`; never a zero value invented for the hint.
- The bulk result equals the single results key by key.
- An unknown key → `FLAG_NOT_FOUND`.
- Under concurrent resolution with store updates (`-race`), each resolution sees either the old or the new documents. Samples provide two flags always updated together.
- Attributes reach the evaluator.
- No telemetry: the factory's `Settings` has no telemetry; the module boundary covers the rest.
- Each failure reports expected vs observed (A4).

## 7. Risks

- **C-003.**
  - Endpoints keep `IResolver`, so the decorator, `errFormat`, and the v1/v2 reason handling are untouched.
  - Every typed outcome is pinned by 1a, and bulk responses by 1b.
  - The moved legacy-proto branches (Q2) and `ERROR` → `GENERAL` (Q3) are the only intended changes; Q3 isn't reachable in practice.
- **NFR-001.** It uses an append-into API with pooled buffers and a single-evaluator fast path, and the read view saves transactions. If allocs/op still rise, step 5 stops and reports with the numbers, rather than relaxing the gate.
- **Concurrency.** The read view fixes the mixed-view bulk resolution (Q4). The contract's consistency case runs under `-race`.
- **Router semantics.** Precedence reuses the flags table's rule (source index). For flagd-only distributions, the fast path keeps today's code path. Mixed distributions are new behaviour covered by the step 7 and step 8 tests.
- **Compat API.** `NewJSON`'s typed methods stay for embedders on the old API. UC-015's guide points them to `typed`.
- **Over-building.**
  - No middleware (UC-005), endpoint factories or event bus (UC-004), builder or manifest (UC-001), or vendor engine (UC-019).
  - The keyvalue engine is a fixture.
- **Containment and a public repository.** No other repository is touched. Plan and PR texts name roles, never people.
