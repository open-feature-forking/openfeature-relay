# Step 18 plan: move the CI helpers from Python to Go (issue #253)

**Status: revision 1, for the opposer.** Base: `main` @ 3488de6b. Step 17 (#250 builds, #251 publish, stacked) is open
and adds Python of its own (section 1).

**Goal.** The Python CI helpers under `.github/scripts/` become one small Go module, `tools/ci`, tested with `go test`.
One language and one test runner for the repository's own tooling. Each port is **behaviour-preserving**: same inputs,
same exit codes, same `GITHUB_OUTPUT` lines, same step summary and annotations, byte for byte where CI or a reader
consumes them.

**Out of scope:**
- the vendored spec lint, `.github/scripts/aiup/` (and `spec-lint.yaml`), stays Python;
- the docs site build (`docs.yaml`, `requirements.txt`, mkdocs) stays Python;
- the shell scripts stay shell (`release-*.sh`, `run-benchmarks.sh`, `testbed-suites.sh`, `render-published-manifest.sh`,
  and step 17's `image-*.sh`, `publish-gate.sh`, `publish-images.sh`). Only the Python they call or embed moves;
- no change to what a PR runs, which flags it sets or what a job reports (drop-in, applied to CI).

## 2. The tools module

- **Location:** `tools/ci`, module path `github.com/open-feature-forking/openfeature-relay/tools/ci`, `go 1.27`.
- **One binary, `relay-ci`, with subcommands** (Q1), one per helper:

  | Subcommand | Replaces |
  |---|---|
  | `relay-ci modules changes …` | `ci-modules.py changes` (same flags) |
  | `relay-ci allocs <base> <head>` | `compare-allocs.py` |
  | `relay-ci pass-sets <a.json> <b.json>` | `compare-pass-sets.py` |
  | `relay-ci test-failures --log … --job … --summary …` | `test-failures.py` |
  | `relay-ci oci check|marking|load|platforms …` | `oci-layout.py` and the two heredocs |
  | `relay-ci publish push|move-main …` | `publish-images.py` |

- **Layout,** so parallel slices never edit the same file:
  - `main.go`: a dispatcher over a registry; S0 writes it once.
  - `cmd_<name>.go` in package `main`: one file per subcommand, which registers itself in `init()`.
  - `internal/<name>/`: the logic and its table tests, one package per helper.
  - `internal/ghactions/`: `GITHUB_OUTPUT`/`GITHUB_STEP_SUMMARY` appends and the `::error`/`::warning`/`::notice`
    escaping, written once in S0 (today duplicated across the Python files).
  - K2 is a test-only package, `tools/ci/workflows/`, with no binary part.
- **Dependencies** (pinned in `go.mod`, nothing else):
  - `golang.org/x/mod` **v0.41.0** (`modfile` for the module graph), added by A;
  - `go.yaml.in/yaml/v3` **v3.0.5** (K2), added by K.

  Both are the versions already in the workspace's build list, so adding `tools/ci` to `go.work` moves no other
  module's resolution. S0 adds a test that `tools/ci` requires no module of this repository.
- **Registration:**
  - `ci-modules.json` gets `"tools/ci": {"test": "make test-module MODULE=tools/ci", "always": true}`;
  - Makefile: `tools/ci` joins `PLAIN_TEST_MODULES`, so `make test` runs it (the `test` job ignores the matrix and runs
    `make test`); `make lint` reaches it through `ALL_GO_MOD_DIRS`;
  - not in `check-package-coverage`'s lists, `GO_LIB_MODULE_DIRS` or any distribution.
- **How jobs run it** (Q2): each job that needs it builds it once,
  `GOWORK=off go build -C tools/ci -trimpath -o "$RUNNER_TEMP/relay-ci" .`, a Makefile target `ci-tool` wrapping the
  same line. `GOWORK=off` so no job needs `make workspace-init` first. The `benchmark` job builds from `head/tools/ci`,
  as it runs the scripts from `head/` today.
- **Startup cost:**
  - jobs that already run `setup-go` (`benchmark`, `test`, testbed jobs, the dry run, the publish jobs) pay one
    compile of a small module: stdlib-only helpers ~2–4 s cold; A's `x/mod` adds a module download, which the
    setup-go cache keyed on `tools/ci/go.sum` absorbs;
  - **`changes` gains `setup-go`** (go 1.27 from the toolcache or a download) plus the compile: estimated 5 s → 20–35 s
    on the critical path of every gated job. A measures it; the budget is +30 s (R1).
- **The fail-open rule survives the build.** Today a crash of `ci-modules.py` sets every flag (`::warning`), and only a
  module missing from the table fails. In Go:
  - a panic is recovered in `modules changes` and writes `all=true` plus every flag, as today;
  - a **build** failure of `relay-ci` (or a setup-go failure) runs a shell fallback in the same step that writes
    `all=true` and every flag true with a `::warning`; the flag names in it are pinned by K2 against the Go
    `FlagPatterns`;
  - the table error keeps exit 1, which the fallback does not catch (distinct exit code).

## 3. The port, per helper

**Characterization first.** Each slice's first commit adds the Go table tests carrying **every case of the Python
test file** (one row per `test_*` method or `subTest`), written red against a stub, before any logic. Then:

- **Parity tests during the transition (Q5).** A Go test in each package runs the Python script and the Go code on
  the same inputs and compares stdout, the files written and the exit code. It skips without `python3`, except under
  `GITHUB_ACTIONS=true`, where it fails. The cutover slice X deletes these tests with the Python. No workflow gets a
  shadow step, so the parallel slices do not touch `build.yaml`.
- **Inputs for parity:** the Python tests' fixtures, plus:
  - A: the `changes` output for 30 real first-parent ranges of `main` (merge commits of the last two weeks, including
    `go.mod`-only, markdown-only, workflow-only and deleted-module changes), plus `pull_request`, `push` with a zero and
    a missing `before`, `workflow_dispatch`, `schedule` and `FULL_CI=true`;
  - B: the five `bench-*.txt` pairs and two real `benchmark` job logs; two real testbed `go test -json` pairs;
  - C: the `test.log` of three failed `test` runs, with and without `-v` output, a timeout panic and a build failure;
  - P: step 17's layouts from a dry-run artifact, and the `registry:2` rehearsal.

**Translation hazards** each slice checks with a row:

| Hazard | Where | Rule |
|---|---|---|
| `fnmatch` `*` matches `/`; `path.Match` does not | A, the prune list (`./distributions/*/build`) | a small `fnmatch` equivalent; a row with a deeper path |
| Python `re` against RE2 | A `FLAG_PATTERNS`, C, B | today's patterns use no lookaround or backreference; a test compiles each and runs every Python row |
| `json.dumps(separators=(',', ':'))`, key order, HTML escaping | A's `test=` output | a struct in today's key order (`name, module, run, coverage, submodule`), `SetEscapeHTML(false)`, a golden line |
| float formatting (`%`, ratios) | B's summary table | goldens from the Python output |
| `str.split()` on any whitespace, `splitlines` on `\r\n` | A `parse_gomod` (replaced by `modfile`), C | rows with CRLF and tabs |
| BFS order of `affected` decides the reason text | A | a sorted queue as today; goldens of the summary |
| `errors="replace"` decoding | A `submodule_of`, C | invalid UTF-8 row |

**Per helper:**

- **A, `modules`.** `parse_gomod` becomes `modfile.ParseLax` (module path and every `require`, indirect included; a
  `replace` without a `require` still gives no edge). `EXTRA_EDGES`, `MANIFEST_GLOBS`, `FLAG_PATTERNS` and the
  `RELAY`/`LEGACY` aliasing move as data. Git stays a `git` subprocess (`rev-parse`, `cat-file`, `diff -z`,
  `ls-tree -z`), as today. `test_ci_modules.py` (the table against the Makefile, via `make -n`) becomes
  `internal/modules/makefile_test.go`. `miss-report` and `--oracle`: Q3.
- **B, `allocs` and `pass-sets`.** `NOISY` keeps every entry and its reason, as a Go map with the same keys.
  `testdata/bench-*.txt` move to `tools/ci/internal/allocs/testdata/` in X; until then the tests read them in place.
- **C, `test-failures`.** The state machine (`RUN`/`CONT`/`PASS`, the output kept for a later `FAIL` under `-v`, the
  timeout panic, the `-` test for a package failure) ports line for line. The `::error` escaping goes through
  `internal/ghactions`. Exit 0 always.
- **K, the workflow tests (K2), K3 and `NoEmbeddedMarkdown`** → `tools/ci/workflows`, run by `make test`.
  - Text checks stay text checks (`regexp` over the file), so the pins keep their meaning; the job splitter keeps its
    regexp.
  - The YAML checks use `go.yaml.in/yaml/v3`: unmarshal into `map[string]any`, and into `yaml.Node` where a check needs
    key order or line numbers. Gotcha: YAML 1.1's `on:` is the boolean `true` in PyYAML but a string key in yaml/v3,
    so the trigger checks read `on` (a row pins it).
  - The SHA-256 pins carry over unchanged (CRLF → LF normalisation as today).
  - `test_flags_follow_the_diff` reads `modules.FlagPatterns` (needs A).
  - `test_publish_gate.py` becomes a Go test that runs `publish-gate.sh` with `bash`.
  - The lint step `pip install pyyaml` goes away with K2.
- **P, `oci` and `publish`.** A stdlib port (`archive/tar`, `net/http`, `crypto/sha256`), no registry library (Q6):
  same allowlist of 7 destinations checked before the first byte, same Basic login from `REGISTRY_USER`/`REGISTRY_TOKEN`,
  `REGISTRY_HOST` limited to localhost for the rehearsal, push by digest, `move-main` ancestor check and `--force`.
  `oci platforms` replaces the heredoc in `release-dry-run.sh`.

## 6. Risks

- **R1, the gate gets slower.** `changes` goes from ~5 s with no Go to setup-go plus a compile, ahead of every gated
  job on every PR. If A measures more than +30 s, X caches the built binary keyed on `hashFiles('tools/ci/**')`
  (actions/cache), or Q2 (c).
- **R2, a silent change of what runs.** A different flag or module set skips a job without failing anything. Against
  it: the 30-range parity in A, goldens of the summary and `GITHUB_OUTPUT`, the fail-open fallback, and X's spot-check.
- **R3, semantics drift** (section 3's hazards). Each has a row.
- **R4, step 17 churn.** K and P port files still in review. They start only after the merge, or stack on #251 and
  re-port any later commit there.
- **R5, two copies.** Between A/B/C/P and X, a fix to a Python helper must land in Go too. The parity tests catch a
  one-sided fix. K deletes the Python K2 in the same PR, so K2 is never doubled.
- **R6, the workspace.** `tools/ci` in `go.work` adds its requirements to the shared build list. Pinned to versions
  already there, with the workspace gate.
- **R7, dependency surface.** Two pinned modules, only in `tools/ci`, in no distribution and no module graph boundary.
  No Dependabot `gomod` entry (Q7).

## 0. Questions for the project lead

- **Q1, the shape of the binary.**
  - (a) One `relay-ci` with subcommands; one build per job.
  - (b) One `main` per helper (`tools/ci/cmd/<name>`); a build per helper.
  - **Recommended:** (a). One compile, one cache key, and the dispatcher keeps slices apart through per-file
    registration.
- **Q2, how jobs get the binary.**
  - (a) `go build` once per job into `$RUNNER_TEMP` (`make ci-tool`).
  - (b) `go run ./tools/ci` at each call (a second call in a job recompiles from the build cache, ~1 s).
  - (c) `changes` builds it once and uploads an artifact; other jobs download it.
  - **Recommended:** (a). (c) couples every job to `changes` and an artifact round-trip costs about what a compile
    does; (b) is fine where a job calls once, but (a) is one rule everywhere.
- **Q3, `miss-report` and `--oracle`.** No workflow calls them since the `test` job stopped using the matrix.
  - (a) Do not port; delete them in X with a line in the PR.
  - (b) Port them as `relay-ci modules miss-report`.
  - **Recommended:** (a). Their tests go with them; the oracle is one `go list -deps -test` loop to rebuild if wanted.
- **Q4, where `ci-modules.json` lives.**
  - (a) Stays at `.github/scripts/ci-modules.json`.
  - (b) Moves to `tools/ci/ci-modules.json`.
  - **Recommended:** (a). The Makefile, CLAUDE.md and every reader name the path; it is configuration of CI, not code
    of the tool.
- **Q5, how both implementations are compared.**
  - (a) Parity tests in Go that run the Python on the same inputs, deleted in X.
  - (b) Shadow steps in `build.yaml` that run both and diff, for a week.
  - **Recommended:** (a). (b) puts every slice on `build.yaml` and costs runner time; (a) covers the recorded real
    ranges, and X's spot-check covers live PRs.
- **Q6, the registry client for P.**
  - (a) Stdlib port of `publish-images.py`.
  - (b) `github.com/google/go-containerregistry`.
  - **Recommended:** (a). It is a line-for-line port of reviewed code and keeps the dependency count at two; (b) is a
    large tree in the job that holds `packages: write`.
- **Q7, Dependabot for `tools/ci`.**
  - (a) None during the PoC; the two pins move by hand.
  - (b) A weekly `gomod` entry for `/tools/ci` in step 17's `dependabot.yml`.
  - **Recommended:** (a). Two modules, no runtime exposure; (b) adds a bot PR stream for tooling.

**Planner defaults (the lead can overrule):** the module path and name `tools/ci` / `relay-ci`; `GOWORK=off` builds;
`internal/ghactions` as the one place for workflow commands; the flag names and every output line unchanged.
