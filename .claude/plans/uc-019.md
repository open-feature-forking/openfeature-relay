## 0a. What the survey found

**Flagsmith's Go engine is reusable** (the opposer verified this). `fs/flagengine` exposes:
- `engine_eval.MapEnvironmentDocumentToEvaluationContext`, which maps features, project segments and identity overrides (as segments) once;
- `engine_eval.MapContextAndIdentityDataToContext`, which sets the identity key to `<env api_key>_<identifier>`;
- `flagengine.GetEvaluationResult`, which returns every flag with `Enabled`, `Value`, `Variant` and `Reason`.

Its compiled dependencies are `blang/semver`, `ohler55/ojg`, `itlightning/dateparse`, `fs/trait` and `crypto/md5`. There is no transport.

**Hashing matches the Python reference engine.** It is `md5(",".join(ids × iterations)) mod 9999 / 9998 × 100`, recomputed with the ids repeated when the result is exactly 100.
- Multivariate splits hash `[feature key, identity key]`, and only when an identity is set.
- `PERCENTAGE_SPLIT` segments hash `[segment key, trait value or identity key]`.

Parity therefore rests on the inputs (R1).

## 0. Questions for the project lead

The recommendation comes first. Wherever flagd-full could change, the recommendation keeps today's behaviour.

- **Q1, where the Flagsmith components live.**
  - **Recommendation:** `contrib/flagsmith/{engine,sync,middleware}`, each its own module with path `R/contrib/flagsmith/<x>`. Moving them out later (#111) only changes the module path.
  - *Alternative:* `engine/flagsmith`, `sync/flagsmith`, `middleware/flagsmith`.

- **Q2, the SSE fetch trigger.**
  - **Recommendation:** a generic `sse` trigger type in its own module, `sync/sse`, **not** added to flagd-full in UC-019 (that is UC-010's call). It connects in `Run`, not in `Init` (finding 4). A stream that is unreachable or refused returns an error, the provider backs off and reconnects, and startup and readiness never depend on it. `Init`, if present, only validates settings. Every example, test and guide lists `{type: poller}` next to `sse`, because an explicit `triggers:` list replaces the poller.
  - *Alternative:* add it to `sync/http`'s factories, which makes it visible in flagd-full's components listing.

- **Q3, FR-028 credentials.**
  - **Recommendation:** an opt-in source key `headersFrom: {"<Header>": {"env": "<VAR>"} | {"file": "<path>"}}` in `core/pkg/sync.SourceConfig`. It is resolved when the source is created and merged over `headers`. The http fetcher, the Flagsmith fetcher and the SSE trigger read it. A missing variable or file is a startup error that names the source and the header, never the value. Sources without the key behave as today.
  - *Alternative:* Flagsmith-only settings. FR-028 then stays `Open`.

- **Q4, mapping reasons and variants.**
  - **Recommendation:**

    | Engine reason | OpenFeature reason |
    |---|---|
    | `DEFAULT` | `STATIC` |
    | `TARGETING_MATCH; segment=…` | `TARGETING_MATCH` |
    | `SPLIT; weight=…` | `SPLIT` |
    | a disabled feature | `DISABLED` |

    The segment name, the weight and the feature id go into metadata as `flagsmithSegment`, `flagsmithWeight` and `flagsmithFeatureId`. The variant is the engine's `Variant`, and `""` becomes no variant.
  - *Alternative:* the engine's reason passed through as an uppercase vendor reason.

- **Q5, booleans and disabled flags (finding 3).** The Flagsmith OpenFeature Go provider reads a boolean from the flag's **value** by default; `WithUsingBooleanConfigValue()` switches it to the enabled state.
  - **Recommendation: match the provider.** The engine setting `booleanFromEnabled` defaults to `false`.
    - **Value mode (default):** every type reads `feature_state_value`. A disabled flag returns reason `DISABLED` and no value (`HasValue=false`), so the client's default applies.
    - **Enabled mode:** a boolean request returns `enabled`, so a disabled flag is `false` with reason `DISABLED`. Other types behave as in value mode.
    - With `hide_disabled_flags`, a disabled flag is `FLAG_NOT_FOUND` for the `client` credential kind and is left out of bulk responses.
  - *Alternative:* enabled mode as the default.

- **Q5b, server-key-only features (G7, finding 8).** The lead knows Flagsmith's API.
  - **Recommendation:** if the environment document marks server-key-only features, the lead names the field, and 3b decodes it and hides those features from `client` keys (BR-004). If it does not, hiding them is an accepted gap. Until the lead answers, 3b proceeds without it.
  - *Alternative:* the implementer looks for the field in Flagsmith's public API documentation (read-only) before 3b.

- **Q6, `updated_at` without a timezone (G5).**
  - **Recommendation:** accept it like the Python engine. The format reads `updated_at` with `dateparse`, assumes UTC, then decodes the rest. A characterization case pins it.
  - *Alternative:* reject the document under A4, naming `updated_at`.

- **Q7, Flagsmith's shared engine test data (finding 1, the blocker).**
  - **Recommendation: commit nothing from it.** The committed cases are:
    - our own hashing vectors, computed independently in the test with `crypto/md5` and `math/big`, which are the spec of the algorithm and not Flagsmith's data;
    - `fs/fixtures/environment.json`, which the client's BSD-3 license covers and which is read from the module cache, not copied;
    - hand-written documents for each segment operator, multivariate weights, identity overrides and `hide_disabled_flags`, checked against `flagengine.GetEvaluationResult` (3c's adapter test).

    An opt-in `make flagsmith-engine-data-check` runs our format and evaluator over a read-only clone of `engine-test-data` at the commit `fs` v5.3.0 records, cloned into a cache outside the repository (`$XDG_CACHE_HOME`). It is never committed and not run in CI.
  - *Q7b:* whether to ask Flagsmith to license `engine-test-data` (BSD-3, like the client). That is the lead's call under containment. If they license it, a later commit can move the check into CI.
  - *Alternative:* no use of the shared data at all.

- **Q8, the flag set of an environment and the middleware's configuration.**
  - **Recommendation:** one document per source. Its flag set is `<environment api_key>`, Flagsmith's client key, which is public by design.
    - The middleware `flagsmith-credential` reads `X-Environment-Key`.
    - Its configuration maps each key (through `env`/`file`, in Q3's form) to a flag set and a kind (`client`, or `server` for `ser.` keys).
    - It binds `flagSetId=<flag set>`, attaches `flagsmith.credential=<kind>`, and answers an unknown or missing key with 401 (A6).
  - *Alternative:* the numeric environment `id` as the flag set.

- **Q9, the command line (#94 gap 3).**
  - **Recommendation:** no `cmd:`, so the distribution keeps flagd's CLI and configuration (UC-019 step 1). An Edge-Proxy-compatible `cmd:` comes later.
  - *Alternative:* a `contrib/flagsmith/cmd` that reads the Edge Proxy's `config.json` now.

- **Q10, the parity oracle (finding 5).** The Edge Proxy answers `/api/v1/flags/` and `/api/v1/identities/`, each flag as `enabled` and `feature_state_value`. It has no variant and no OpenFeature reason.
  - **Recommendation:**
    - **Edge Proxy answers:** they check **enabled and value** per flag, identity and traits. Answers are recorded with `make refresh-flagsmith-oracle` against `flagsmith/edge-proxy`, pinned by digest and fed the same recorded document; the image's engine version is recorded alongside. The recorded answers run in every CI run, and a live differential runs under `FULL_CI`.
    - **Variants and reasons:** pinned against `GetEvaluationResult` plus Q4's table.
    - **Mode:** the oracle compares in value mode (Q5) and records the mode.

    The image is pulled read-only, and no Flagsmith service is contacted.
  - *Alternative:* recorded answers only.

- **Q11, #94 part 1 (finding 2).** Part 1 is the configuration proxy: an `environment-document/` passthrough for SDKs in local evaluation, `/proxy/health/*`, endpoint readiness, and a test with an SDK in local evaluation. It needs no engine.
  - **Recommendation:** this plan realizes UC-019's text, which is evaluation behind OFREP. #94 part 1 is its own slice after UC-017, because flagd-sync plays the same role. #94 stays open, and no PR here claims it.
  - *Alternative:* the passthrough slice goes first, before PR 3. It is the shorter path to a working Edge Proxy replacement, but it is outside UC-019's main scenario.

- **Q12, GO Feature Flag.**
  - **Recommendation:** a separate later plan (`uc-019-goff.md`) with its own boundary review. UC-019 moves to `Implemented` on Flagsmith, with GOFF as an accepted gap that slice owns.
  - *Alternative:* GOFF in this plan.

- **Q13, A2: what a refused key does (finding 10).**
  - **Recommendation:** a fetcher may return an error that wraps the new `sync.ErrSourceRefused`.
    - **Before the first accepted delivery of the source:** the provider stops, and the runtime exits non-zero naming the source (A2 steps 1–2).
    - **After it:** the provider logs the error without the credential, keeps serving the last document and keeps retrying, as A3 does. `staleAfter` then takes the relay out of readiness.

    A2 is amended to match ("System stops the vendor distribution if no delivery of the source was accepted yet"), and its reference is corrected to UC-003 BR-008.
  - *Alternative:* stop on any refusal, which is A2's current wording. A key rotation or a transient WAF 403 would then take every environment down.

## 5. Risks

- **R1, engine parity: the biggest risk.** The hash is identical, but results match only if the inputs do:
  - the identity key `<api_key>_<identifier>` is what current engines use, while an older Edge Proxy hashed another key;
  - the feature key and the segment keys;
  - trait typing (`ToString(5.0)` is `"5"`);
  - `updated_at` (Q6);
  - boolean mode (Q5).

  Mitigation: the Edge Proxy image is pinned by digest, with its engine version recorded; value mode in the oracle; our own vectors and documents; the opt-in shared-data check. The oracle covers enabled and value only, so variants and reasons rest on `fs`'s own engine. A difference between Flagsmith's two engines goes to the lead and is not patched in our mapping (BR-005).
- **R2, `fs` is a client module.** An upgrade can change the engine silently. Renovate bumps run the vectors, the documents and the oracle.
- **R3, cost.** `GetEvaluationResult` evaluates every segment and feature per call, and JSONPath conditions parse every time; 3f measures this. Each SSE event costs one full, paginated download before the hash says "unchanged". Comments and keepalives do not signal. Skipping a fetch by the event's `updated_at` (as Flagsmith's client does) needs fetcher state the trigger contract does not give, so it is a known cost here and a candidate for a Flagsmith-aware trigger later.
- **R4, credentials.** Q3 keeps keys off the command line. Section 2 and PR 7 scan logs, responses and `cmdline`. Q13 never logs the key.
- **R5, drop-in.** flagd-full's manifest is untouched. `headersFrom` and `ErrSourceRefused` are inert for today's sources, and the pins prove it.
- **R6, boundaries and FIPS.** The engine module has no transport. `crypto/md5` means there is no FIPS variant (G10). The `depguard` FIPS rule only checks direct imports, so contrib stays out of `test-fips` deliberately, and the guide says so.
