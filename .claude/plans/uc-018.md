### Facts from today's code

- `JSON.SetState` (json.go:120) parses, transposes `$evaluators`, validates default variants and calls `store.Update`.
  - Schema violations only warn (json.go:497-501).
  - `validateDefaultVariants` returns at the first bad flag, which for map-form flags depends on Go map iteration order.
- `store.Update` (store.go:222) derives `flagSetId` (set metadata, then a per-flag override, then `nilFlagSetId`, a per-process UUID, query.go:29), patches metadata and applies priority.
  - `idIndex` is (flagSetId, key) without the source.
  - A lower-priority write over a higher-priority row is skipped.
  - A higher-priority source dropping a key deletes the shared row.
- Who uses what today:
  - The evaluator and flagd's services hold `store.IStore` (only `Get`, `GetAll`, `Watch`, `Update`). `flagd/pkg/evaluation.NewEvaluator` wraps `evaluator.NewJSON`.
  - `runtime.updateAndEmit` calls `r.Evaluator.SetState` inside the `flagSync` span (runtime.go:143-153), then readiness, then `SyncService.Emit`.
  - The phase-1 pin `runtime_span_test.go:99-104` and `runtime_test.go:150-152` (gomock `SetState`) build `Runtime` as struct literals.
- Outside this repository, the Go in-process provider uses `*store.Store` from `store.NewFlags()`, calls `evaluator.SetState`, diffs `GetAll` around it, and puts `err.Error()` into its `PROVIDER_ERROR` event.

## 3. Design in brief

- **`core/pkg/configformat`**: interfaces and data. It imports `store`, `logger` and `model`.
  - `type ConfigurationFormat interface { Type() string; Accept(ctx context.Context, in Input) (Result, error) }`
  - `Input{Source, Data string /* JSON text */, Selector string, IncrementalUpdate bool}`
  - `Result{Documents []DocumentReport; Dropped []Rejection}`
  - `DocumentReport{FlagSet, Version string; FlagKeys, Added, Updated, Removed []string}`. Every key list is sorted, and `FlagSet` is `""` for the unnamed flag set.
  - `Rejection`: an error `{Source, Entry, Reason}`
  - `type Factory interface { Type() string; Create(Settings) (ConfigurationFormat, error) }`
  - `Settings{Store *store.Store; Logger *logger.Logger; Config map[string]any}`
  - `const DefaultType = "flagd"`
  - Contract: `Accept` applies all of its documents for the source or none. On error the store is unchanged. Callers serialize `Accept` per store.
- **`core/pkg/store`**:
  - Exported `FlagSetID(flag model.Flag, setMetadata model.Metadata) string` is the **single** derivation. It returns `""` for the unnamed set, and the store maps `""` to `nilFlagSetId` internally. `Update` uses it.
  - New `documents` memdb table, id (format, source, flag set), holding `Document{Format, Source, FlagSet, Version string; FlagKeys []string; Value any}`.
  - `Documents(format, source string) []Document`.
  - `Apply(ApplyRequest{Format, Source string; Flags []model.Flag; SetMetadata model.Metadata; Documents []Document; Incremental bool})` writes flag rows (same derivation, patching and priority as `Update`) and documents in one transaction. `Update(...)` becomes `Apply` without documents.
  - `IStore` is unchanged. `Apply` and `Documents` are on `*Store` only (finding 3, option a).
  - Vendor formats pass no flags, so the flags table, which the JsonLogic evaluator reads, never sees their documents (BR-002).
- **`core/pkg/configformat/flagd`**: flagd's configuration format.
  - It moves out of `evaluator`: schema compilation, `transposeEvaluators`, `configToFlagDefinition`, `validateDefaultVariants`, `warnUnsafeNumericVariants`, `isSafeRange`, and the `Definition`/`Evaluators`/`Flags` types (no users outside the package).
  - `Validate(in Input) (Definition, error)` is pure and checks flags in sorted key order, so the named entry is deterministic (today it is random among several faulty ones).
  - `Accept` = `Validate`, then group by `store.FlagSetID`, then fingerprint each flag (SHA-256 of its canonical JSON), compare with the previous `Document.Value` map to get added, updated and removed, set Version = SHA-256 over the sorted fingerprints, then `Apply`.
  - It imports no evaluator package and no `jsonlogic` (BR-005, NFR-011).
- **`core/pkg/configformat/formattest`**: the configuration format contract, `Run(t testing.TB, f configformat.Factory, s Samples)`. Cases follow UC-008's row:
  - accept valid
  - reject invalid; the rejection names the source and *one of* the sample's declared faulty entries
  - store unchanged after a rejection
  - correct keys, flag set, version stability (same input, same version) and change, added, updated, removed
  - replaces only the delivering source
  - replaces only the flag sets of an incremental update
  - dropped entries named (only if the samples declare some)

  Each failure prints its expected and its observed result (A1).
- **Evaluator compat.** `JSON.SetState` is deprecated:
  - If its `IStore` is a `*store.Store`, it calls the flagd format's `Accept`.
  - Otherwise it calls `Validate` and then `IStore.Update`, which is safe for external `IStore` implementers.
  - The error is unchanged in both paths.
  - The evaluator imports `configformat/flagd`; that direction is allowed, and UC-014 removes it.
- **Runtime (resolves the blocker, finding 1, option a).**
  - `Runtime` gains `Formats map[string]configformat.ConfigurationFormat`, keyed by **source**.
  - `updateAndEmit` looks the source up there. Found: it calls `Accept`. Not found, which includes a nil map and every source using flagd's format: it calls `r.Evaluator.SetState` exactly as today.
  - The existing `flagSync` span (scope `jsonEvaluator`, attr `feature_flag.source`, status `flagSync error` plus `RecordError`) wraps whichever of the two calls runs.
  - Every existing `Runtime` literal and gomock expectation therefore keeps working unchanged, and flagd's format is reached through the evaluator's compat wrapper.
  - `from_config.go` adds to `Formats` only sources that name a non-default format, built from a registry: `Config.ConfigurationFormats []configformat.Factory`, empty in flagd-full.
  - A source naming an unknown format is skipped (Q3). `from_config.go` filters it out of `SyncProviders` before it builds sources, the store, `sourceReadiness` and sync providers. It logs an error naming the source and the available formats (`flagd` plus registered types, sorted), and flagd starts with the remaining sources. If every source is skipped, flagd behaves as it does today with no sources.
  - `SourceConfig.Format string \`json:"format,omitempty"\`` is read from `--sources` JSON and the config file (viper and mapstructure match by name); `-f` URIs name none.
  - On a `Rejection` the runtime logs source and entry (A3), and it logs the report at debug.
- **Example extension:** module `test/configformat-example` with its own `go.mod`, `replace` to `../../core` and `../../flagd`.
  - A toy "keyvalue" format: `{"environment": "<flag set>", "flags": {"<key>": <value>}}`. It rejects a non-object `flags` or a null value and names the key.
  - Its factory, samples with declared faulty entries, the contract run, and runtime tests for A2, A3 and A5.
  - It runs in CI through a new Makefile target (finding 5).

## 6. Risks

- **C-003.**
  - flagd-full's sources never go through the new runtime branch: `Formats` stays empty without a non-default format.
  - Rows, error texts, priority and incremental semantics are pinned by the shared table.
  - The single `FlagSetID` derivation is used by both `Update` and `Apply`.
  - The named entry for map-form flags with **several** faulty flags becomes deterministic (sorted). Today it is random, so no stable behaviour is lost; the table pins one faulty entry per case.
- **In-process provider (read only).** `SetState`, `IEvaluator`, `IStore`, `store.NewFlags` and `GetAll` are unchanged. Its `*store.Store` takes the `Accept` path with the same rows and errors. It compiles and behaves as before; UC-014 moves it to `Accept` and change reports.
- **External `IStore` implementers** keep the `Validate` + `Update` path.
- **NFR-005, NFR-011.**
  - `configformat/flagd` imports jsonschema and flagd-schemas, no OTel, gRPC, `jsonlogic` or evaluator. The opposer checked the planned imports, and depguard plus the boundary target in step 6 enforce it.
  - `formattest` and `core/internal/flagconfigtest` import `testing`. No production package imports them, and the boundary gate checks that.
- **NFR-006.** No new core dependency: memdb is already in core, and `crypto/sha256` is stdlib and FIPS-approved.
- **Sync cost.** Fingerprinting adds SHA-256 per flag per sync. It is measured by `BenchmarkSetState` (reported). The evaluation hot path is untouched (gating benchmark).
- **Concurrency.** `Apply` is one memdb transaction. The previous document is read outside it, which is safe because callers serialize: the runtime holds `r.mu`, and the in-process provider runs one sync loop. That rule is documented on `Accept`.
- **Over-building.**
  - No event bus, router, evaluator factory or flag sync format selection.
  - The registry is a slice in `Config` that UC-004/UC-001 replace.
  - `Settings` carries only store, logger and config.
- **C-005.** No protobuf change.
- **Upstream.** PRs 1–4 are shaped for upstream. PR 5 and the UC status are incubator-only.
